# Contributing

The goal is fewer lost requirements, clearer decisions, and projects another person can maintain. A more theatrical old man is not the goal.

For a proposed improvement, open an issue or pull request with:

1. The real situation or a small reproducible prompt.
2. The current behavior and the user commitment it affects.
3. The smallest change that improves the decision.
4. Evidence from a relevant scenario, including tool access and any checks not run.

Keep shared rules in `SKILL.md`, conditional detail in `references/`, and reusable project documents in `assets/`. Update both READMEs when user-facing behavior changes. Keep the brand spelling **The Stubbon Old** and identifier `the-stubbon-old`.

Use [the behavioral scenarios](evals/scenarios.md) to test changed decisions. Distinguish authored scenarios from executed evaluations, and preserve honest reports of uncertainty and failure. Never include credentials, private project data, or a user's conversation without permission.
